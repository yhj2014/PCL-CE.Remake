# 11 · 测试体系（PCL.Core.Test）

测试项目 `PCL.Core.Test` 使用 **MSTest**，在 CI 中跨 Linux / Windows / macOS 运行。除了常规单元测试，它还包含一组“架构测试”，用源码扫描与程序集引用检查来守护分层边界。

## 1. 技术栈

| 项 | 值 |
|---|---|
| 目标框架 | `net10.0` |
| 输出 | 类库 |
| 测试框架 | `MSTest.TestFramework` / `MSTest.TestAdapter` `4.5.3` |
| 测试 SDK | `Microsoft.NET.Test.Sdk` `18.12.0` |
| 其他 | `fNbt`、`SQLitePCLRaw.bundle_e_sqlite3` |
| 引用 | `PCL.Core`、`PCL.Core.UI`、`PCL.Platform`、`PCL.Launcher.Core`、`PCL.Launcher` |
| 排除 | `Net/**`（不编译） |

`TestAssemblyInit` 在程序集级别注册 `CodePagesEncodingProvider`，保证 GBK 等编码测试可用：

```csharp
[AssemblyInitialize]
public static void Initialize(TestContext context)
    => Encoding.RegisterProvider(CodePagesEncodingProvider.Instance);
```

`TestServiceProvider` 是测试用的最小 `IServiceProvider`，支持 `Add<T>` 与 `DisposeCount` 观察，用于生命周期/容器相关测试，避免引入完整 DI 容器。

## 3. 架构测试

架构测试位于 `Architecture/` 与根目录，使用“读取源码 + 反射程序集引用”的方式，防止架构腐化。

### 3.1 程序集引用边界

`ArchitectureTest`：

- `LauncherCore_DoesNotReferenceWpf`：业务核心不得引用 WPF。
- `Core_DoesNotReferenceWpf`：核心层不得引用 WPF。
- `Core_DoesNotReferenceUiOrAvalonia`：`PCL.Core` 不得引用 `PCL.Core.UI`、`PCL.Platform`、Avalonia。
- `Platform_DoesNotReferenceUiOrAvalonia`：平台层不得引用 UI/Avalonia。
- `CoreUi_DoesNotReferencePlatform`：UI 适配层不得引用平台实现。

### 3.2 源码扫描边界

| 测试 | 规则 |
|---|---|
| `PlatformArchitectureTest` | `UsesWindowsPaths` 不得泄漏到业务代码；`PCL.Core` 中的 `OperatingSystem.Is*` / `RuntimeInformation.IsOSPlatform` 只能出现在底层白名单文件 |
| `DialogArchitectureTest` | 禁止同步弹窗入口（`DialogService.Instance.Show(`、`ForceWait`、`ModalFrame`、`SyncHelper`、同步文件选择等） |
| `WindowCompositionArchitectureTest` | 约束窗口组合方式（避免绕过 `WindowHost`） |
| `LocalizationUsageTest` | 检查硬编码文本/本地化 key 使用 |
| `AssetUsageTest` / `ImageResourceLayoutTest` | 资源路径与布局规范 |
| `ThemeResourceKeysTest` | 主题资源 key 一致性 |
| `XamlSecurityValidatorTest` | XAML 安全校验 |
| `NavigationArchitectureTest` | 页面注册/导航依赖约束 |

这些测试会在 CI 的 `dotnet test` 中执行，失败即阻断合并。

### 3.3 为什么需要架构测试

项目同时包含核心层、平台层、UI 适配层、业务层和界面层。仅靠代码评审很难长期保证“核心层不引用 Avalonia”“业务层不直接弹窗”。把这些约束写成测试，可以在编译/测试阶段自动发现违规。

## 5. 编写测试的约定

1. **不依赖网络**：网络测试使用本地 WebServer / Mock Handler，禁止访问真实站点。
2. **不依赖用户目录**：使用临时目录（`Path.GetTempPath()` + 唯一子目录），测试后清理。
3. **不依赖 UI**：纯逻辑测试放在 `PCL.Core.Test`；需要 Avalonia 的测试应使用 headless 方式并显式标记。
4. **文件系统隔离**：涉及 `Paths` 的测试要重定向到临时目录，或使用内存 Provider 替代真实存储。
5. **确定性**：避免依赖当前时间/随机数；必要时注入时钟或固定种子。
6. **命名**：`<被测类型>Test`，方法名描述行为与期望；复杂场景加注释。
7. **架构约束**：新增项目引用时，先确认不会破坏 `ArchitectureTest`。

## 6. 运行测试

```bash
# 全部测试（CI 同款）
dotnet test PCL.Core.Test/PCL.Core.Test.csproj -c CI -p:Platform=AnyCPU --nologo --blame-hang --blame-hang-timeout 120s

# 本地快速运行
dotnet test PCL.Core.Test/PCL.Core.Test.csproj -c Debug -p:Platform=AnyCPU

# 只跑某个类
dotnet test PCL.Core.Test/PCL.Core.Test.csproj -c Debug -p:Platform=AnyCPU --filter "FullyQualifiedName~PageNavigationStateMachineTest"
```

CI（`.github/workflows/build-test.yml`）：

- `test` Job 在 `ubuntu-latest`、`windows-latest`、`macos-latest` 三个平台运行；
- 使用 .NET SDK `11.0.x`（项目目标 `net10.0`）；
- 15 分钟超时，`--blame-hang-timeout 120s` 用于定位挂起测试。

## 7. 提交前检查清单

- `dotnet build "PCL Community Edition.slnx" -c Debug -p:Platform=x64` 无错误。
- `dotnet test` 全部通过。
- 架构测试通过（不引入跨层引用、不恢复同步弹窗入口）。
- 新增/修改公共 API 时补充测试。
- 新增本地化 key 时通过 `LocalizationUsageTest` 与 `LocalizationTest`。
- 新增页面/导航时通过 `NavigationArchitectureTest` 与 `PageFactoryDependencyTest`。
