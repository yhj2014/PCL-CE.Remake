# 12 · 构建、运行与发布

## 1. 环境要求

### 1.1 开发环境

| 项 | 要求 |
|---|---|
| .NET SDK | .NET 10 SDK 及以上（CI 使用 `11.0.x`） |
| 操作系统 | Windows / Linux / macOS 均可开发 |
| IDE | JetBrains Rider、Visual Studio 2022+、VS Code + C# Dev Kit 均可 |
| 额外 | Linux 打包需要 `appimagetool`、`nfpm`；macOS 签名/公证需要 Apple 证书与凭据 |

### 1.2 运行环境

| 平台 | 要求 |
|---|---|
| Windows | Windows 10 1809 (17763)+ / Windows 11；.NET 10 Runtime；x64/ARM64 |
| Linux | 常见 glibc 桌面发行版（Ubuntu 22.04+、Fedora 43+、Arch 等）；glibc ≥ 2.27；.NET 10 Runtime；X11（Wayland 实验性）；x64/ARM64 |
| macOS | macOS 12+；.NET 10 Runtime；Apple Silicon 与 Intel |

发布产物默认是**框架依赖**（`--no-self-contained`），因此用户机器需要安装 .NET 10 Runtime。

## 2. 构建

```bash
# 还原 + 构建整个解决方案
dotnet build "PCL Community Edition.slnx" -c Debug -p:Platform=x64

# 只构建入口项目
dotnet build PCL.Launcher/PCL.Launcher.csproj -c Debug -p:Platform=x64
```

配置与平台：

```text
配置：Debug | CI | Release | Beta
平台：AnyCPU | x64 | ARM64
```

推荐显式指定 `-p:Platform=x64`（或 `ARM64`），以保证原生库与运行时标识一致。

## 3. 本地运行

```bash
dotnet run --project PCL.Launcher/PCL.Launcher.csproj -c Debug -p:Platform=x64
```

注意事项：

- Linux 需要可用的图形会话（X11/Wayland），无头环境无法启动 UI。
- 首次运行会创建数据目录（见第 7 节）。
- 若出现单实例锁冲突，关闭已运行的实例或删除 `instance.lock`。
- `PCL.Launcher` 是 `WinExe`，直接双击运行时不会显示控制台；开发时建议用 `dotnet run` 或在 IDE 中启动。

## 4. 测试

```bash
# 全部测试（CI 同款）
dotnet test PCL.Core.Test/PCL.Core.Test.csproj -c CI -p:Platform=AnyCPU \
  --nologo --blame-hang --blame-hang-timeout 120s

# 本地快速测试
dotnet test PCL.Core.Test/PCL.Core.Test.csproj -c Debug -p:Platform=AnyCPU
```

详见 [11-测试体系.md](11-测试体系.md)。

## 5. 发布

### 5.1 `scripts/publish.sh`

```bash
# 用法：scripts/publish.sh <rid> [configuration] [output-root]
scripts/publish.sh win-x64 Beta dist
scripts/publish.sh linux-x64 Release dist
scripts/publish.sh osx-arm64 Beta dist
```

行为：

1. 根据 RID 推导 `Platform`（x64/ARM64）；
2. 清理并创建 `dist/<rid>`；
3. `dotnet publish PCL.Launcher.csproj -c <config> -r <rid> -p:Platform=<platform> --no-self-contained -o <out>`；
4. 删除 `.pdb`；
5. 调用 `scripts/verify-artifact.sh` 校验原生库隔离与 PDB。

支持的 RID：

| RID | Platform | 产物 |
|---|---|---|
| `win-x64` | x64 | Windows x64 目录（CI 打包为 `.zip`） |
| `win-arm64` | ARM64 | Windows ARM64 目录（`.zip`） |
| `linux-x64` | x64 | Linux x64 目录（后续打包 AppImage/deb/rpm） |
| `linux-arm64` | ARM64 | Linux ARM64 目录 |
| `osx-x64` | x64 | macOS Intel 产物 |
| `osx-arm64` | ARM64 | macOS Apple Silicon 产物 |

### 5.2 Linux 打包

```bash
scripts/package-linux.sh linux-x64 Beta 2.15.1 dist
```

依赖：

- `nfpm`（deb/rpm）
- `appimagetool`（AppImage）
- 可选 `APPIMAGE_RUNTIME`

产物：

- `PCL2_CE_<config>_linux_<arch>.AppImage`
- `.deb`、`.rpm`
- 打包后会验证 desktop entry、AppRun、文件权限与 AppImage 可解包性。

### 5.3 macOS 打包

```bash
scripts/package-macos.sh osx-arm64 Beta 2.15.1 dist
```

行为：

1. 发布到临时目录；
2. 组装 `PCL CE.app/Contents`（`MacOS`、`Resources`、`Info.plist`）；
3. 写入启动包装脚本 `launcher`，设置：
   - `PCL_PACKAGE_KIND=macos-app`
   - `PCL_DATA_DIR=${PCL_DATA_DIR:-$HOME/PCLCE}`
   - `PCL_MINECRAFT_DIR=${PCL_MINECRAFT_DIR:-$HOME/PCLCE/.minecraft}`
4. 可选 Developer ID 签名、公证、staple。

相关环境变量：

| 变量 | 用途 |
|---|---|
| `CODESIGN_IDENTITY` | Developer ID Application 证书名 |
| `APPLE_ID` / `APPLE_TEAM_ID` / `APPLE_APP_SPECIFIC_PASSWORD` | 公证凭据 |
| `PCL_BUILD_VERSION` | `CFBundleVersion`，默认取 `metadata.json` 的 `version.code` |
| `PCL_SKIP_CODESIGN=1` | 跳过签名 |
| `PCL_SKIP_NOTARIZATION=1` | 跳过公证 |

CI 再生成 `.zip` 与 `.dmg`。

### 5.4 产物校验

`scripts/verify-artifact.sh <rid> <dir>`：

- 禁止出现 `.pdb`；
- Linux 产物不得包含 Windows/macOS 原生库，且必须包含：
  `libSkiaSharp.so`、`libHarfBuzzSharp.so`、`libe_sqlite3.so`、`libminiaudioex.so`；
- Windows 必须包含：
  `av_libglesv2.dll`、`e_sqlite3.dll`、`libSkiaSharp.dll`、`libHarfBuzzSharp.dll`、`miniaudioex.dll`；
- macOS 必须包含：
  `libSkiaSharp.dylib`、`libHarfBuzzSharp.dylib`、`libe_sqlite3.dylib`、`libminiaudioex.dylib`、`libAvaloniaNative.dylib`。

用途：防止 `dotnet publish` 混入其他平台原生库，导致运行时加载错误。

## 6. CI / CD

| 工作流 | 触发 | 内容 |
|---|---|---|
| `.github/workflows/build-test.yml` | push 到 `dev`、PR、手动 | 跨 6 个 RID 构建 + 三平台测试 |
| `.github/workflows/reusable-build.yml` | 被调用 | 发布产物、打包 Windows/Linux/macOS |
| `.github/workflows/release-publish.yml` | 手动（`workflow_dispatch`） | 构建、生成 changelog、创建 GitHub Release、签名并上传产物 |
| `.github/workflows/mirrorchyan_uploading.yml` | 发布相关 | 上传到 MirrorChyan |
| `.github/workflows/mirrorchyan_release_note.yml` | 发布相关 | 生成 MirrorChyan 发布说明 |

`build-test.yml` 的构建矩阵：

```text
windows_x64   win-x64    x64
windows_ARM64 win-arm64  ARM64
linux_x64     linux-x64  x64
linux_ARM64   linux-arm64 ARM64
macos_ARM64   osx-arm64  ARM64
macos_x64     osx-x64    x64
```

测试 Job 在 `ubuntu-latest`、`windows-latest`、`macos-latest` 上运行，超时 20 分钟，测试命令 15 分钟超时。

发布流程（`release-publish.yml`）：

1. 手动输入配置（`Release`/`Beta`）与版本号；
2. 六个 RID 并行构建与打包；
3. `git-cliff` 生成 changelog；
4. 创建/更新 Draft Release（Beta 为 prerelease）；
5. 下载产物，使用 sigstore 签名并上传。

## 7. 数据目录与配置

| 内容 | 位置 |
|---|---|
| 应用数据 | 默认可执行目录下 `PCL/`；打包形态或不可写时 `~/PCLCE` |
| 共享配置 | `%APPDATA%/PCLCE/config.v1.json`（Windows）或对应平台的 ApplicationData |
| 本机共享数据 | LocalApplicationData 下 `PCLCE` |
| 临时文件 | 系统临时目录下 `PCLCE` |
| Minecraft 目录 | 默认 `PCL/.minecraft` 或 `~/PCLCE/.minecraft`，可用 `PCL_MINECRAFT_DIR` 覆盖 |
| 日志 | `Paths.Data/Log` |

配置损坏处理：

- 损坏文件重命名为 `*.failbackup`；
- 若存在 `.bak`，自动回退；
- 启动日志会记录失败原因。

## 8. 环境变量

### 8.1 路径与形态

| 变量 | 说明 |
|---|---|
| `PCL_DATA_DIR` | 覆盖应用数据目录（支持 `~`） |
| `PCL_MINECRAFT_DIR` | 覆盖默认 Minecraft 目录 |
| `PCL_PACKAGE_KIND` | 安装形态（`deb`/`rpm`/`appimage`/`macos-app` 等），影响路径选择 |
| `APPIMAGE` | AppImage 运行时自动设置，用于识别形态 |
| `PCL_PATH` / `PCL_PATH_SHARED` / `PCL_PATH_LOCAL` / `PCL_PATH_TEMP` | 仅 Debug 构建生效，单独覆盖各路径 |

### 8.2 日志与调试

| 变量 | 说明 |
|---|---|
| `PCL_LOG_LEVEL` | 日志级别（`Trace`/`Debug`/`Info`/`Warning`/`Error`/`Fatal`，或 `warn`） |
| `PCL_LOG_CONSOLE` | 强制输出到控制台（`1`/`true`） |
| `--verbose` | 启动参数，等价于 Trace |
| `--console` | 启动参数，输出到控制台 |
| `PCL_DEBUG_LAYOUT` | 布局诊断（`1`） |
| `PCL_DEBUG_WINDOW_SIZE` | 主窗体尺寸调试 |
| `PCL_DEBUG_SMOKE_PAGES` / `PCL_DEBUG_SMOKE_DWELL` | 页面冒烟测试 |
| `PCL_DISABLE_DEBUG_HINT` | 关闭调试提示 |
| `PCL_ANIMATION_TIMER` | 使用独立动画计时器（`1`） |
| `PCL_TEST_NETWORK` | 测试中允许真实网络（`1`，默认禁止） |

### 8.3 Linux 图形

| 变量 | 说明 |
|---|---|
| `PCL_USE_WAYLAND=1` | 尝试原生 Wayland；失败自动回退 X11 |
| `PCL_FORCE_X11` | 强制 X11 |

Wayland 需要 `libwayland-client` 与 `libxkbcommon`。

### 8.4 密钥与发布

| 变量 | 说明 |
|---|---|
| `PCL_MS_CLIENT_ID` | 微软 OAuth Client ID |
| `PCL_CURSEFORGE_API_KEY` | CurseForge API Key |
| `PCL_SENTRY_DSN` | Sentry DSN |
| `PCL_TELEMETRY_KEY` | 遥测密钥 |
| `PCL_NAID_CLIENT_ID` / `PCL_NAID_CLIENT_SECRET` | Natayark ID |
| `PCL_LINK_SERVER_ROOT` | 联机大厅服务器根地址 |
| `PCL_LOBBY_DEFAULT_SECRET` | 大厅默认密钥 |
| `PCL_GITHUB_SHA` | 构建提交 SHA |
| `PCL_WRITE_SECRET=1` | 编译期允许把 `PCL_*` 环境变量写入程序集 |
| `DOTNET` | 脚本使用的 dotnet 路径（`publish.sh` 默认 `$HOME/.dotnet/dotnet`，`package-linux.sh` 默认 `dotnet`） |

> 安全提示：`PCL_WRITE_SECRET=1` 只在受控发布环境使用，本地开发保持关闭。

## 9. 常见问题

### 9.1 启动无界面 / 崩溃

1. 查看 `Paths.Data/Log` 下当日日志；
2. 使用 `PCL_LOG_LEVEL=Trace` 重试；
3. Linux 无 `DISPLAY`/`WAYLAND_DISPLAY` 时无法启动 UI；
4. 缺少 .NET 10 Runtime 时，检查系统是否安装。

### 9.2 Linux Wayland 异常

- 先尝试 `PCL_FORCE_X11=1`；
- 确认安装 `libwayland-client`、`libxkbcommon`；
- 查看日志中 Wayland 初始化失败原因。

### 9.3 单实例冲突

- 程序使用 `instance.lock`（共享本地数据目录，备用临时目录）；
- 异常退出可能残留锁；确认无运行实例后可删除锁文件；
- 单实例转发通过命名管道 `RpcService.PipePrefix@{pid}`。

### 9.4 配置损坏

- 删除/备份 `config.v1.*`；
- 程序会自动尝试 `.bak`，并把损坏文件改名为 `.failbackup`；
- 插件/实例级配置在实例目录 `PCL/config.v1.yml`。

### 9.5 macOS 无法打开

- 未签名/未公证的构建会被 Gatekeeper 拦截；
- 正式发布使用 Developer ID 签名 + 公证 + staple；
- 开发构建可用 `xattr -dr com.apple.quarantine` 临时绕过（仅本地测试）。

### 9.6 发布产物缺少原生库

- 运行 `scripts/verify-artifact.sh <rid> <dir>`；
- 确认 `dotnet publish` 的 `-r` 与 `-p:Platform` 匹配；
- 检查是否误把多个 RID 发布到同一目录。

### 9.7 构建平台不匹配

- 解决方案同时支持 `AnyCPU`/`x64`/`ARM64`；
- 发布时必须使用 `-p:Platform` 与 RID 对应，否则可能引用错误架构的原生库。
