# 07 · UI 适配层（PCL.Core.UI）

`PCL.Core.UI` 是 `PCL.Core` 与 Avalonia 之间的适配层。它只做两件事：

1. 把核心层定义的 UI 抽象（调度器、剪贴板、文件对话框、资源、本地化、主题、通知）实现为 Avalonia 版本；
2. 提供一套独立于 Avalonia 原生动画系统的动画引擎。

它**不包含**启动器业务页面，也不包含组合根；页面与 DI 装配在 `PCL.Launcher`。

## 1. 服务注册

`AvaloniaUiServiceRegistration.AddAvaloniaUi(services, kind)`：

| 核心接口 | 实现 | 平台分支 |
|---|---|---|
| `IUiDispatcher` | `AvaloniaUiDispatcher` | 通用 |
| `IClipboardService` | `ClipboardService` | 通用 |
| `IFileDialogService` | `FileDialogService` | Windows/macOS |
| `IFileDialogService` | `LinuxFileDialogService` | Linux（依赖 `IExternalCommandRunner`） |
| `IResourceStore` | `ResourceStore` | 通用 |
| `ILocalizationBackend` | `LocalizationBackend` | 通用（依赖 `IUiDispatcher`） |
| `IThemeBackend` | `ThemeBackend` | 通用 |
| `ISystemThemeProvider` | `SystemThemeProvider` | Windows/macOS |
| `ISystemThemeProvider` | `LinuxSystemThemeProvider` | Linux（依赖 `IExternalCommandRunner`） |
| `ISystemNotificationService` | `WindowsNotificationService` | Windows |
| `ISystemNotificationService` | `LinuxNotificationService` | Linux |
| `ISystemNotificationService` | `MacOsNotificationService` | macOS |

`UiModuleFactory.Create(kind)` 仅返回 `UiModule`（平台种类），具体服务由 DI 注册。

## 2. 应用与窗口宿主

### 2.1 `ApplicationHost`

`ApplicationHost` 实现 `IApplicationHost`，负责：

- 持有 Avalonia `Application` 与主窗体；
- 订阅 `Startup` / `Exit` 事件；
- 在 `Startup` 时触发 `Lifecycle.OnLoading()`；
- 捕获 UI 线程未处理异常并转交 `Lifecycle.OnException`；
- 统一在 `Run()` 中进入 Avalonia 消息循环。

关键接口：`PCL.Core/Platform/IApplicationHost.cs`。

### 2.2 `WindowHost`

`WindowHost` 实现 `IAvaloniaWindowHost`，负责：

- 窗口创建/显示/关闭；
- 窗口大小、位置、状态；
- 顶层窗口引用；
- 与 `WindowContext`（业务侧）绑定。

相关接口：`IAvaloniaApplicationHost`、`IAvaloniaWindowHost`。

> 注意：`ApplicationHost` 内部有少量 `Console.Error` 输出用于“Avalonia 尚未初始化”的极端场景。这是框架级兜底，业务代码仍必须使用日志服务。

## 3. 线程调度

`AvaloniaUiDispatcher` 实现 `IUiDispatcher`：

```csharp
bool CheckAccess();
void Post(Action action);
Task InvokeAsync(Action action);
Task<T> InvokeAsync<T>(Func<T> func);
```

使用要点：

- 所有 UI 操作必须回到 UI 线程。
- 从后台线程调用 `Post`/`InvokeAsync`，不要直接操作控件。
- 业务层（如 `PageRouter`、`DialogService`）已内建线程切换。

## 4. 剪贴板与文件对话框

### 4.1 `ClipboardService`

- 读写文本。
- 写入文件路径列表（平台支持时）。
- 失败时记录日志并返回明确结果。

### 4.2 `FileDialogService` / `LinuxFileDialogService`

- 打开文件、保存文件、选择文件夹。
- 支持过滤器、默认文件名、初始目录。
- Linux 版本在 Avalonia 对话框不可用/不理想时，通过 `IExternalCommandRunner` 调用 `zenity`/`kdialog` 等系统工具作为回退。

## 5. 资源存储

`ResourceStore` 实现 `IResourceStore`：

- 读取 `avares://` 资源（图片、字体、图标包）。
- 统一资源 URI 规则。
- 与 `PCL.Launcher/Assets`、`PCL.Localization/Languages` 配合。

核心层通过 `Basics.GetResourceStream` / `GetImageUrl` 访问资源，最终落到这里。

## 6. 本地化

### 6.1 `LocalizationBackend`

实现 `ILocalizationBackend`：

- 从 Avalonia 资源字典加载语言。
- 提供 `Get(key)` 与键存在性检查。
- 语言切换时通过 `IUiDispatcher` 通知 UI 刷新。

### 6.2 `LocExtension`

XAML 标记扩展：

```xml
<TextBlock Text="{ui:Loc Key=LaunchButtonText}" />
```

- 在 XAML 中直接取本地化文本。
- 语言切换时自动更新。
- 键不存在时回退为键名并记录警告。

### 6.3 `LocalizationTextSource`

为无法使用标记扩展的场景（代码/绑定）提供文本源，语言变化时触发通知。

## 7. 主题

| 类型 | 职责 |
|---|---|
| `ThemeBackend` | 应用主题资源字典、切换深浅色、恢复自定义资源 |
| `SystemThemeProvider` | Windows/macOS 读取系统深浅色 |
| `LinuxSystemThemeProvider` | Linux 通过 `gsettings`/桌面环境命令读取 |

`ThemeResourceRestorer`（动画目录下）用于在主题切换/动画结束后恢复被临时覆盖的资源。

## 8. 系统通知

`NotificationServiceBase` 提供统一的通知构造与降级逻辑，三个平台实现：

- `WindowsNotificationService`：通过 PowerShell/Toast 或系统 API 发送。
- `LinuxNotificationService`：`notify-send`。
- `MacOsNotificationService`：`osascript`。

所有实现都通过 `IExternalCommandRunner` 执行外部命令，并在失败时回退到应用内提示。

## 9. 动画引擎

这是 `PCL.Core.UI` 中体量最大的部分，位于 `Animation/`。它不是 Avalonia `Animation` 的封装，而是独立的帧驱动系统。

### 9.1 运行时结构

```text
AnimationService (全局调度)
├── IClock / IUIClock
│   ├── AvaloniaRenderingClock   (跟随 Avalonia 渲染帧)
│   ├── StopwatchClock           (独立计时)
│   └── UiFramePump              (UI 帧泵，含 Release 诊断版本)
├── IAnimation
│   ├── AnimationBase
│   │   ├── FromToAnimationBase
│   │   │   ├── DoubleFromToAnimation
│   │   │   ├── PointFromToAnimation
│   │   │   ├── ThicknessFromToAnimation
│   │   │   ├── MatrixFromToAnimation
│   │   │   ├── NColorFromToAnimation
│   │   │   ├── NRotateTransformFromToAnimation
│   │   │   └── NScaleTransformFromToAnimation
│   │   ├── ActionAnimation
│   │   └── AnimationGroup
│   │       ├── ParallelAnimationGroup
│   │       └── SequentialAnimationGroup
├── IAnimationFrame / FromToAnimationFrame / ActionAnimationFrame
├── IValueProcessor（按类型插值）
└── IEasing（大量缓动函数）
```

### 9.2 关键类型

| 类型 | 职责 |
|---|---|
| `AnimationService` | 注册动画、按帧推进、暂停/恢复、完成回调 |
| `AnimationBase` | 动画基类：时长、延迟、循环、缓动、状态 |
| `FromToAnimationBase` | 起止值动画基类 |
| `AnimationGroup` | 动画组合（并行/顺序） |
| `AnimationTaskObserver` | 以 `Task` 观察动画完成 |
| `AnimationStatus` | 状态枚举 |
| `AnimationValueType` | 值类型标识 |
| `AnimationData` / `AnimationExtensions` | 参数与链式配置 |
| `IUIAccessProvider` / `AvaloniaUiAccessProvider` | 把动画应用到 Avalonia 对象 |
| `ValueProcessorManager` | 按类型选择插值器 |
| `IEasing` 及大量实现 | 线性、Quad、Cubic、Quartic、Quintic、Sine、Expo、Circular、Back、Elastic、Bounce、Fluent |
| `AnimationPresets` | 预置动画（页面切换、淡入淡出等） |
| `AnimationRegistration` | 启动时注册预置动画/值处理器 |

### 9.3 使用方式（概念示例）

```csharp
var animation = new DoubleFromToAnimation
{
    From = 0,
    To = 1,
    Duration = TimeSpan.FromMilliseconds(200),
    Easing = new CubicEaseOut()
};
animation.ApplyTo(element, OpacityProperty);
AnimationService.Run(animation);
```

实际 API 以源码为准。动画系统支持：

- 值类型：`double`、`Point`、`Thickness`、`Matrix`、`NColor`、`NRotateTransform`、`NScaleTransform`。
- 组合：并行、顺序、嵌套。
- 时钟：跟随渲染帧或独立计时，避免 UI 卡顿时动画突变。
- 诊断：`UiFramePump.Diagnostics` 在 Release 下为轻量版本。

### 9.4 调试配置

`Config.Debug.AnimationSpeed` 控制动画速度倍率，便于观察慢动作/快速验证。

## 10. 与其他层的关系

- `PCL.Core` 只定义 `IUiDispatcher`、`IClipboardService` 等接口。
- `PCL.Core.UI` 提供 Avalonia 实现，但不引用 `PCL.Launcher`。
- `PCL.Launcher` 在组合根调用 `AddAvaloniaUi(kind)`，并在 `App.axaml.cs` 中安装字体、主题、提示、剪贴板拦截器。
- 业务层（`PCL.Launcher.Core`）通过核心接口间接使用 UI 能力，不直接引用本层。

## 11. 扩展建议

- 新增一个核心 UI 抽象：先在 `PCL.Core/Platform`（或 `PCL.Core/UI`）定义接口，再在本层实现并注册。
- 新增动画值类型：实现 `IValueProcessor` 并在 `ValueProcessorManager` 注册；必要时增加 `FromToAnimation` 子类。
- 新增平台通知：继承 `NotificationServiceBase`，在 `AvaloniaUiServiceRegistration` 注册。
- 不要在本层加入业务页面或业务服务；保持“纯适配”定位。
