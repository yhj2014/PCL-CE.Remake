# 04 · IO、网络、存储与工具

本章覆盖 `PCL.Core/IO`、`PCL.Core/Utils` 以及相关平台工具。这些是业务层高频依赖的“硬基础设施”。

## 1. 文件与目录

### 1.1 `Files`（partial 拆分）

`PCL.Core/IO/Files.cs` 及 5 个 partial 文件按职责拆分：

| 文件 | 内容 |
|---|---|
| `Files.cs` | 常量、路径拼接、存在性/大小/时间、复制/移动/删除、重命名、回收站 |
| `Files.Sync.cs` | 同步读写文本/二进制、编码检测、按行读写 |
| `Files.Async.cs` | 异步读写、流复制、带进度与取消 |
| `Files.Hash.cs` | 文件哈希（MD5/SHA1/SHA256/SHA512/MurmurHash2） |
| `Files.Json.cs` | JSON 序列化/反序列化（含源生成上下文兼容） |
| `Files.Archive.cs` | ZIP/压缩包枚举、解压、创建（SharpZipLib） |

常用能力：

```csharp
Files.ReadText(path);
await Files.WriteTextAsync(path, text);
Files.Copy(source, target, overwrite: true);
Files.Delete(path, toRecycleBin: true);
string hash = Files.HashFile(path, HashType.SHA256);
```

注意点：

- 所有公共方法都处理路径规范化与异常包装。
- 大量操作会先确保父目录存在。
- 回收站删除走平台层（`IRecycleBinService`），不支持时回退永久删除并记录日志。
- 压缩包路径穿越（zip slip）会被拒绝。

### 1.2 `Directories`

- 创建/删除/复制/移动目录。
- 递归枚举（支持通配符与排除）。
- 计算目录大小。
- 清理空目录。
- 删除可选择进回收站。

### 1.3 `Ini`

- 轻量 INI 解析/写入，保留注释与顺序。
- 用于兼容旧配置/第三方启动器文件。
- 支持节（section）、键值、默认值读取。

### 1.4 `ByteStream` / `StringStream`

- `ByteStream`：在 `byte[]` 上提供类似 `Stream` 的读写（`ReadInt32`、`ReadVarInt`、`ReadString` 等），常用于 NBT/网络协议。
- `StringStream`：逐段读取字符串，适合解析紧凑文本格式。

### 1.5 `PipeComm`

- 命名管道通信常量与辅助方法。
- `PipeEncoding`、`PipeEndingChar` 被单实例转发、RPC 共用。
- 处理连接超时与读写结束符。

## 2. HTTP 栈

`PCL.Core/IO/Net/Http` 不是简单封装 `HttpClient`，而是一套带连接管理、代理、缓存与扩展方法的请求框架。

### 2.1 主要类型

| 类型 | 职责 |
|---|---|
| `HttpRequest` | 请求构建与发送：方法、URL、头、Body、超时、重试、进度、取消 |
| `HttpServer` | 极简 HTTP 服务器：路由注册、请求处理、静态响应 |
| `HttpRouteResponse` | 路由响应模型 |
| `HttpResponseException` | 非成功状态码异常 |
| `HttpProxyManager` | 代理配置：系统代理、自定义代理、认证 |
| `HostConnectionHandler` | 按主机复用/限制连接（`SocketsHttpHandler` 配置） |
| `HttpCacheHandler` | HTTP 磁盘缓存（ETag/Last-Modified/过期） |
| `HttpBasicExtension` / `HttpHeaderExtension` / `HttpContentExtension` / `HttpSenderExtension` / `HttpResponseExtension` | 链式扩展方法 |

### 2.2 请求流程

```mermaid
flowchart LR
    A[业务代码 HttpRequest] --> B[代理选择 HttpProxyManager]
    B --> C[DNS/DoH 解析]
    C --> D[连接管理 HostConnectionHandler]
    D --> E[缓存检查 HttpCacheHandler]
    E --> F[发送请求]
    F --> G[状态码校验/反序列化]
    G --> H[返回结果]
```

补充说明：

- `HttpRequest` 支持 `GET/POST/PUT/DELETE`、表单、JSON、流式上传/下载。
- 下载支持进度回调、限速、断点续传（与业务层下载器配合）。
- 失败重试由请求层与业务层共同控制（Polly 用于部分策略）。
- 代理来自 `ISystemProxyProvider`（平台层解析系统代理）或配置中的自定义代理。
- 缓存元数据由 `HttpCacheMetadata` 保存，命中时直接返回，减少重复下载。

### 2.3 代理

`HttpProxyManager` 负责：

- 读取系统代理（Windows WinINET、Linux 环境变量/KDE、macOS 系统设置，由平台层提供）。
- 合并用户自定义代理与认证信息。
- 为不同目标主机选择直连或代理。
- 处理代理不可用时的回退。

## 3. DNS 与网络

### 3.1 DNS

| 类型 | 职责 |
|---|---|
| `DnsQuery` | DNS 查询封装（A/AAAA/SRV/TXT 等） |
| `DnsSrvResource` | SRV 记录解析（Minecraft 服务器地址常用） |
| `WeightedDnsRacerClient` | 多 DNS 服务器并发竞速，按权重/延迟选择最快结果 |

`Config.Network.EnableDoH` 控制是否使用 DNS over HTTPS。权重竞速的意义：不同地区 DNS 质量差异大，取最快响应可显著减少解析卡顿。

### 3.2 网络服务

| 类型 | 职责 |
|---|---|
| `NetworkService` | 网络状态、连通性检测、在线/离线判断 |
| `NetworkHelper` | IP/端口/URL 解析、地址规范化 |
| `NetworkInterfaceUtils` | 网卡枚举、IPv4/IPv6 地址选择 |
| `SocketExtension` | Socket 连接超时、读写辅助 |
| `SocketForward/` | TCP 端口转发：`TcpForwardBuilder`、`TcpForwardConfig`、`TcpForwardWorker` |

TCP 转发用于联机大厅/端口映射场景：Builder 组装监听端与目标端，Worker 负责双向拷贝与统计。

## 4. 缓存体系

`PCL.Core/IO/Storage/Cache` 是本地缓存的核心，基于 SQLite。

### 4.1 结构

| 类型 | 职责 |
|---|---|
| `CacheService` | 对外统一缓存 API：按命名空间读写、TTL、标签、批量操作 |
| `CacheServiceManager` | 创建/管理多个 `ICacheService` 实例 |
| `ICacheService` | 缓存契约 |
| `SqliteCacheStorage` | SQLite 持久化实现（默认） |
| `FileCacheStora` | 文件式缓存实现 |
| `SchemaManager` | 建表、迁移、索引 |
| `CachePolicy` / `CacheOptions` | 过期、容量、清理策略 |
| `CacheEvictionService` | 后台清理过期/超限缓存 |
| `CacheStats` | 命中率、条目数、大小统计 |
| `CacheKeys` | 键规范化与命名空间 |
| `CacheEntry` / `InstanceCacheRow` / `ComponentCacheRow` | 数据模型 |

### 4.2 表与模型

- `InstanceCacheRow`：实例级缓存（版本信息、资源索引等）。
- `ComponentCacheRow`：社区资源/组件缓存（项目详情、文件列表等）。
- `CacheEntry`：通用键值条目（键、值、过期时间、标签、创建/访问时间）。
- 通过 Dapper 访问，`SQLitePCLRaw.bundle_e_sqlite3` 提供原生 SQLite。

### 4.3 使用建议

- 为缓存键加命名空间前缀，避免不同模块冲突。
- 明确 TTL；对强一致数据不要缓存。
- 大对象放文件缓存，小对象放 SQLite。
- 清理策略由 `CacheEvictionService` 在 `Running` 阶段后台执行。

## 5. HashStorage

`PCL.Core/IO/Storage/HashStorage.cs` 提供内容寻址存储：

- 以内容哈希为键保存文件（类似 Git object）。
- 相同内容只存一份，节省磁盘。
- 支持校验与去重。
- 适合存放下载缓存、资源文件、整合包解压中间产物。

## 7. 二进制差异

`Utils/Diff`：

- `IBinaryDiff`：二进制差异接口。
- `BsDiff`：BSDiff 算法实现，用于启动器增量更新（下载补丁而非完整包）。
- 与更新模块配合：比较旧版本与新版本文件，生成/应用补丁并校验哈希。

## 8. 编码约定

- IO 操作必须处理异常并记录日志，不要静默吞掉。
- 大文件使用流式 API，避免一次性读入内存。
- 网络请求必须支持取消（`CancellationToken`）。
- 路径拼接统一使用 `Path.Combine` + `Paths`，不要硬编码分隔符。
- 哈希/加密不要自行实现算法，使用 `Utils/Hash`、`Utils/Encryption`。
- 文件删除默认进回收站，除非明确需要永久删除。

这些基础能力被 `PCL.Launcher.Core` 的下载、安装、启动、缓存模块大量复用，是理解业务层的前置知识。
