# 06 · 平台抽象与原生实现

跨平台能力通过“**核心层定义接口 + 组合根选择实现 + 运行时门面访问**”实现：

- `PCL.Core/Platform`：接口、能力描述、平台检测、`ApplicationRuntime`；
- `PCL.Platform`：Windows / Linux / macOS / POSIX 的原生实现；
- `PCL.Launcher`：在启动时选择实现并注册到 DI。

## 1. 平台检测与运行时

### 1.1 `PlatformKind`

```csharp
public enum PlatformKind { Windows, Linux, MacOs }
```

### 1.2 `PlatformDetector`

`PlatformDetector.Detect()` 读取 `RuntimeInformation`，返回 `PlatformKind`，并在不支持的平台上尽早抛出清晰错误。

### 1.3 `ApplicationServices`

组合根产出的“服务包”：

```csharp
public sealed class ApplicationServices
{
    public PlatformModule Platform { get; init; }
    public UiModule Ui { get; init; }
    public IServiceProvider? Services { get; set; }
}
```

### 1.4 `ApplicationRuntime`

全局运行时门面：

```csharp
ApplicationRuntime.Initialize(services);   // 仅一次
ApplicationRuntime.Current;                // 应用级服务
ApplicationRuntime.GetRequiredService<T>();
ApplicationRuntime.Shutdown();             // 幂等
```

`ApplicationRuntime.Current.Platform` 暴露 `PlatformModule`（含 `Kind`、`Capabilities`），`Current.Ui` 暴露 `UiModule`。这样业务代码无需感知具体平台类型。

### 1.5 `PlatformModule` / `UiModule`

仅承载“平台种类 + 能力集合”，不包含行为：

```csharp
public sealed class PlatformModule
{
    public required PlatformKind Kind { get; init; }
    public required IPlatformCapabilities Capabilities { get; init; }
}
```

行为通过 DI 解析对应接口获得。

## 2. 平台能力（`PlatformCapabilities`）

| 能力 | Windows | Linux | macOS |
|---|---|---|---|
| `SupportsBundledLauncher` | true | false | false |
| `SupportsShortcutIcon` | false | true | false |
| `NativeLibraryExtensions` | `.dll` | `.dll/.so/.dylib` | `.dll/.so/.dylib` |
| `SupportsWindowsStoreDependencies` | true | false | false |
| `SuppressAltMenu` | true | false | false |
| `SupportsDisplayProtocolSelection` | false | true | false |

这些值会影响启动参数、Natives 替换、菜单行为、Linux 显示协议（X11/Wayland）选择等。

## 6. 平台差异说明

### 6.1 Windows

- 代理来自 WinINET/注册表。
- 快捷方式使用 `.lnk`。
- GPU 偏好通过注册表写入（`WindowsGpuPreferenceService`）。
- 通知使用 Toast（AppUserModelID，见 `WindowsAumidHelper`）。
- Natives 为 `.dll`。
- 提权通过 UAC。
- 启动脚本为 `.bat`。

### 6.2 Linux

- 代理来自环境变量与 KDE 配置（`KdeProxyConfigParser`）。
- 回收站遵循 FreeDesktop 规范。
- 显示协议可选 X11/Wayland（`LinuxDisplayProtocol`、`Config.Debug.LinuxProtocol`）。
- 启动环境需要处理 `LD_LIBRARY_PATH`、`XDG_*`、窗口系统变量（`LinuxLaunchEnvironmentService`）。
- 启动脚本为 `.sh`，服务端为 `.sh`。
- 快捷方式为 `.desktop`。
- 不支持 GPU 偏好（明确降级）。
- AppImage 形态下路径与图标有特殊处理。

### 6.3 macOS

- 代理来自系统配置（`MacOsProxyConfigParser`）。
- 回收站为 `~/.Trash`。
- 快捷方式为 `.command`/应用包。
- 启动脚本为 `.command`。
- 不支持 GPU 偏好与 Linux 启动环境。
- Objective-C 互操作通过 `PlainToolkit.ObjectiveC`。

## 7. 如何新增一个平台能力

1. 在 `PCL.Core/Platform` 定义接口，必要时在 `PlatformCapabilities` 增加能力位。
2. 在 `PCL.Platform` 为每个平台实现：
   - 公共逻辑放 `Shared/`；
   - 平台特有逻辑放 `Windows/`、`Linux/`、`MacOS/`。
3. 在 `PlatformServiceRegistration.AddPlatformServices` 中按 `PlatformKind` 注册。
4. 若完全不支持某平台，使用明确的“Unsupported”实现，并在日志/文档中说明，而不是抛空实现。
5. 在 `PCL.Core.Test` 增加对应测试（尤其是路径与规则类）。
6. 业务层通过 `ApplicationRuntime.GetRequiredService<T>()` 或构造注入使用，不要直接 `new` 平台类型。

## 8. 设计约束

- 平台实现不得引用 Avalonia。
- 平台实现不得包含启动器业务逻辑（如安装、下载）。
- 所有平台服务必须可被 DI 单例解析，且线程安全。
- 原生调用失败时返回可诊断错误/日志，不允许 `NotImplementedException` 占位。
- 平台差异通过能力位或接口暴露，业务层用 `Capabilities` 分支，而不是散落的 `#if`。
