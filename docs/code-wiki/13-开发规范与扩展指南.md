# 13 · 开发规范与扩展指南

## 1. 代码规范

### 1.1 通用

- 目标框架 `net10.0`，`LangVersion 15.0`，启用 `Nullable` 与 `ImplicitUsings`。
- 文件级命名空间使用 `namespace X;`。
- 私有字段使用 `_camelCase`；常量使用 `PascalCase`。
- 异步方法以 `Async` 结尾，参数带 `CancellationToken`。
- 公共 API 需要 XML 文档或清晰命名；复杂逻辑需要注释说明“为什么”，而不是“做了什么”。
- 不在代码中硬编码用户可见文本，使用 `Lang.Text("Key")`。
- 不在源码中硬编码密钥，使用 `Secrets` / 环境变量。

### 1.2 强制要求（本项目开发规范）

以下要求来自项目约定，提交前必须满足：

1. **禁止** 使用 `Console.WriteLine` 作为正式实现；统一使用 `LogWrapper` / `ILogger` / `LifecycleContext`。
2. **禁止** `throw new NotImplementedException()`。
3. **禁止** `// TODO` 或任何形式的占位符。
4. **禁止** 空壳实现。
5. 每个方法必须有完整、真实的实现。
6. 必须处理异常（`try-catch`），并记录日志。
7. 必须有日志记录（Debug/Info/Warning/Error）。
8. 异步方法使用 `async/await`，不要 `.Result` / `.Wait()`。
9. Windows / macOS / Linux 各自完整实现；不得用 `#if` 跳过某平台。确实不支持的功能必须确认并记录到 `PLATFORM_TODO.md`。
10. 核心逻辑必须有单元测试；测试不依赖网络/文件系统（使用 Mock / 临时目录隔离）。
11. `dotnet test` 必须全部通过。

### 1.3 提交前检查

```bash
# 构建
dotnet build "PCL Community Edition.slnx" -c Debug -p:Platform=x64

# 测试
dotnet test PCL.Core.Test/PCL.Core.Test.csproj -c Debug -p:Platform=AnyCPU

# 规范检查：结果必须为空
grep -r "Console.WriteLine" src/ && echo "FAIL"
grep -r "NotImplementedException" src/ && echo "FAIL"
grep -r "// TODO" src/ && echo "FAIL"
```

> 仓库目录不是 `src/`，实际检查时把根目录或具体项目目录替换进去。若历史代码存在违规，修改相关文件时应顺手修复，不要新增违规。

### 1.4 架构边界（必须遵守）

| 规则 | 说明 |
|---|---|
| `PCL.Core` 不引用 Avalonia / UI / 业务层 | 只定义抽象 |
| `PCL.Core.UI` 不引用 `PCL.Platform` | UI 适配与原生平台解耦 |
| `PCL.Platform` 不引用 Avalonia / UI | 只做原生能力 |
| `PCL.Launcher.Core` 不引用 Avalonia | 业务逻辑与界面解耦 |
| 业务层不直接弹窗 | 通过 `Ui/` 契约 + Bridge |
| 平台差异集中在平台层 | 业务代码不写 `OperatingSystem.Is*` 分支 |
| 页面导航只在 UI 线程 | 后台线程用 `Post`/`InvokeAsync` |

这些规则由 `PCL.Core.Test/Architecture` 与源码扫描测试守护。

## 3. 常见扩展配方

### 3.1 新增生命周期服务

```csharp
using PCL.Core.App.IoC;

namespace PCL.Core.App.Essentials;

[LifecycleService(LifecycleState.Running, Priority = 50)]
[LifecycleScope("my-service", "我的服务", asyncStart: true)]
public sealed partial class MyService
{
    [LifecycleStart]
    private static async Task _StartAsync(LifecycleContext context)
    {
        try
        {
            context.Info("MyService starting");
            // 真实初始化
            await Task.CompletedTask;
        }
        catch (Exception ex)
        {
            context.Error("MyService start failed", ex);
            throw;
        }
    }

    [LifecycleStop]
    private static async Task _StopAsync(LifecycleContext context)
    {
        try
        {
            context.Info("MyService stopping");
            await Task.CompletedTask;
        }
        catch (Exception ex)
        {
            context.Error("MyService stop failed", ex);
        }
    }
}
```

要点：

- 类必须 `partial`，由 `LifecycleScopeGenerator` 生成 `ILifecycleService`。
- `Identifier` 全局唯一。
- 选择正确的状态：越早越影响启动速度；`Running` 适合后台任务。
- `SupportAsync` 由 `[LifecycleScope]` 第三个参数控制。
- 不要在没有日志的情况下吞异常。

### 3.2 新增配置项

在 `PCL.Core/App/Config.cs` 对应组中：

```csharp
[ConfigGroup("MyFeature")]
public static partial class MyFeatureConfigGroup
{
    [ConfigItem<bool>("MyFeatureEnabled", true, ConfigSource.Shared)]
    public partial bool Enabled { get; set; }

    [ConfigItem<int>("MyFeatureThreads", 4, ConfigSource.Local)]
    public partial int Threads { get; set; }
}
```

使用：

```csharp
if (!Config.MyFeature.Enabled) return;
var threads = Math.Clamp(Config.MyFeature.Threads, 1, 32);
```

注意：

- 键名全局唯一；已有键不要随意改名（会影响升级用户）。
- 需要迁移时在 `ConfigMigration` 增加逻辑。
- 敏感值使用 `ConfigSource.SharedEncrypt`。
- 实例级配置使用 `ConfigSource.GameInstance` 与 `argument`。
- 修改后检查生成的 `ConfigService.g.cs` 是否包含新项。

### 3.3 新增页面

1. **ID**：在 `Navigation/PageIds.cs` 或 `SubPageIds.cs` 增加常量。
2. **描述**：在对应 `Catalog/*PageModule.cs` 中注册：

```csharp
Yield(new PageDescriptor(
    Id: PageIds.MyPage,
    TitleKey: "MyPage_Title",
    IconKey: "IconMyPage",
    Tab: MainTab.Tools,
    LeftWidth: 210,
    DefaultSubPage: SubPageIds.MyPage_Main,
    Groups: [...],
    SubPages:
    [
        Sub(SubPageIds.MyPage_Main, "MyPage_Main", (sp, route) => new PageMyPageMain())
    ],
    CreateHost: (sp, page) => ActivatorUtilities.CreateInstance<PageMyPageHost>(sp, page)));
```

3. **宿主**：实现 `IPageHost`（左栏/右栏/标题/缓存）。
4. **视图**：`Views/Pages/...` 控件；需要 DI 的左栏在 `LauncherServiceRegistration` 注册。
5. **ViewModel**：继承 `ViewModelBase`，通过构造注入服务。
6. **本地化**：在 `PCL.Localization/Languages/*.axaml` 添加 key。
7. **测试**：补充 `PageCatalogTest` / `PageFactoryDependencyTest` 断言。

### 3.4 新增平台能力

1. 在 `PCL.Core/Platform` 定义接口。
2. 在 `PCL.Platform` 实现：
   - 通用逻辑放 `Shared/`；
   - 平台特化放 `Windows/`、`Linux/`、`MacOS/`；
   - 不支持时提供明确的“Unsupported”实现并记录日志。
3. 在 `PlatformServiceRegistration.AddPlatformServices` 注册。
4. 在 `PlatformModuleFactory` 视需要增加能力位。
5. 业务层通过构造注入或 `ApplicationRuntime.GetRequiredService<T>()` 使用。
6. 添加平台测试（尽量用纯逻辑/临时目录）。

### 3.5 新增 UI 契约与 Bridge

业务层需要新的界面交互时：

1. 在 `PCL.Launcher.Core/Ui` 定义接口：

```csharp
public interface IMyFeatureUi
{
    Task<bool> ConfirmAsync(string message, CancellationToken token = default);
}
```

2. 在 `PCL.Launcher/UI/Bridges`（或 `UiInteraction.cs`）实现：

```csharp
internal sealed class MyFeatureUiBridge : IMyFeatureUi
{
    public Task<bool> ConfirmAsync(string message, CancellationToken token = default)
        => DialogPresenter.ShowConfirmAsync(message, token);
}
```

3. 在 `UiServiceRegistration.Configure` 注册为单例。
4. 在业务代码中构造注入接口，不要直接引用 `PCL.Launcher`。

### 3.6 新增本地化 key / 语言

1. 在所有 `PCL.Localization/Languages/*.axaml` 添加同名 key（至少 `zh-CN`、`en-US`）。
2. 运行时资源通过 `PCL.Core.UI` 链接同一批文件，无需复制。
3. 使用 `Lang.Text("Key")` 或 `{ui:Loc Key=Key}`。
4. 不要拼接句子；需要参数时使用格式化：
   `Lang.Text("Download_Progress", current, total)`（若该 API 支持）或先取模板再格式化。
5. 运行 `LocalizationTest` / `LocalizationUsageTest` 检查缺失 key 与硬编码。

### 3.7 新增本地化属性

```csharp
public partial class MyViewModel : LocalizedObservableObject
{
    [LocalizedProperty("MyFeature_Title")]
    public partial string Title { get; }
}
```

生成器会补全 `Title => Lang.Text("MyFeature_Title")`；语言切换时由基类刷新通知。

### 3.8 新增加载器

1. 在 `PCL.Launcher.Core/Download` 增加下载/安装逻辑。
2. 在 `McInstallPipeline.CreateInstallLoader` 注册加载器。
3. 在 `InstanceJsonMerge` 处理 JSON 合并与继承。
4. 在 `McInstanceInfo` 识别新加载器。
5. 在 `Ui`/下载页增加选项（如需要）。
6. 补充组合约束（`GetCombinationError`）与测试。

### 3.9 新增整合包格式

1. 在 `Modpack/` 增加解析器，识别格式并解析为 `McInstallRequest`。
2. 处理游戏版本、加载器、资源清单、覆盖文件。
3. 在导入入口注册格式。
4. 补充 `Modpack` 相关测试（可使用本地压缩包样本）。

## 4. 日志与异常处理规范

```csharp
try
{
    await DoWorkAsync(token);
    LogWrapper.Info("Work completed");
}
catch (OperationCanceledException) when (token.IsCancellationRequested)
{
    LogWrapper.Info("Work cancelled");
    throw;
}
catch (Exception ex)
{
    LogWrapper.Error("Work failed", ex);
    throw;
}
```

要求：

- 捕获后要么恢复并记录，要么带上上下文重新抛出。
- 不要捕获 `Exception` 后静默返回默认值（除非明确是可选功能）。
- 用户可见错误使用 `ActionLevel` / 业务异常消息；技术细节写日志。
- 敏感信息（AccessToken、密码、Cookie）必须脱敏。

## 5. 已知平台限制

| 功能 | Windows | Linux | macOS | 说明 |
|---|---|---|---|---|
| GPU 偏好设置 | ✅ | ❌ | ❌ | 平台不支持，使用 `UnsupportedGpuPreferenceService` |
| Linux 启动环境准备 | ❌ | ✅ | ❌ | `LinuxLaunchEnvironmentService` |
| Wayland 原生 | — | 实验性 | — | 失败自动回退 X11 |
| musl（Alpine） | — | 不支持 | — | 产物未验证 |
| 系统通知 | ✅ Toast | `notify-send` | `osascript` | 依赖外部命令/系统权限 |
| 回收站 | ✅ | FreeDesktop | `~/.Trash` | 不支持时回退永久删除并记录 |

新增平台限制时，必须同步更新本文档与（如适用）`PLATFORM_TODO.md`。

## 6. 调试技巧

| 场景 | 方法 |
|---|---|
| 启动卡住 | `PCL_LOG_LEVEL=Trace`，查看生命周期状态日志 |
| 页面不显示 | `PCL_DEBUG_SMOKE_PAGES` 冒烟遍历；检查 `PageRegistry` 日志 |
| 布局异常 | `PCL_DEBUG_LAYOUT=1` |
| 动画异常 | `PCL_ANIMATION_TIMER=1` 切换计时器 |
| Linux 图形问题 | `PCL_FORCE_X11=1` / `PCL_USE_WAYLAND=1` |
| 配置异常 | 删除配置或利用 `.bak` / `.failbackup` |
| 单实例冲突 | 检查 `instance.lock` 与命名管道 |
| 网络问题 | 检查代理配置、`Config.Network.EnableDoH`、日志中的 DNS/HTTP 记录 |
| 平台服务缺失 | 查看 `UiServiceRegistration.Validate` / DI 构建异常 |

## 7. 术语表

| 术语 | 含义 |
|---|---|
| **实例（Instance）** | 一个 Minecraft 版本目录（`versions/<name>`），可独立配置 Mod、存档、隔离策略 |
| **版本隔离（Indie）** | 让实例使用自己的 `mods`/`saves`/配置目录，而非共享 `.minecraft` |
| **加载器（Loader）** | Forge、NeoForge、Fabric、Quilt、OptiFine、LiteLoader、LabyMod 等 |
| **安装管线** | `McInstallPipeline` 组装的下载/安装任务序列 |
| **启动阶段（Launch Stage）** | 启动流程中的 10 个阶段（Java、登录、补全、参数、Natives、预启动、自定义、启动、等待窗口、结束） |
| **Bridge** | 业务 UI 契约在界面层的实现 |
| **PageHost** | 页面宿主，负责左栏/右栏/标题与缓存 |
| **PageCatalog** | 所有页面描述的只读快照 |
| **生命周期服务** | 由 `[LifecycleService]`/`[LifecycleScope]` 声明、按状态启动的服务 |
| **ConfigSource** | 配置存储来源（Shared/SharedEncrypt/Local/GameInstance） |
| **DoH** | DNS over HTTPS |
| **Scaffolding** | 联机大厅自定义信令协议 |
| **EasyTier** | P2P 虚拟组网组件，用于联机 |
| **MMC** | MultiMC 整合包格式 |
| **CE** | Community Edition，社区版 |

## 8. 贡献流程建议

1. 从 `dev` 拉分支：`feat/xxx` 或 `fix/xxx`。
2. 先读相关 Wiki 章节与源码，确认架构边界。
3. 小步提交，提交信息遵循 Angular 规范。
4. 本地构建 + 测试 + 规范 grep。
5. 如涉及 UI，附截图/录屏；如涉及平台，注明测试环境。
6. PR 指向 `dev`，关联 Issue。
7. 使用生成式 AI 工具时，按项目 AI 方针披露，并对内容正确性负责。
