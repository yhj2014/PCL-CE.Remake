# 10 · 源码生成器（PCL.Core.SourceGenerators）

`PCL.Core.SourceGenerators` 是一组基于 Roslyn 的**增量源生成器**，在编译期把重复样板代码生成出来。它把“声明”与“实现”分离：开发者只写特性和 partial 成员，生成器负责补全。

## 1. 项目配置

`PCL.Core.SourceGenerators.csproj`：

- `TargetFramework = netstandard2.0`（分析器要求）
- `IsRoslynComponent = true`
- 引用 `Microsoft.CodeAnalysis.CSharp`、`Microsoft.CodeAnalysis.Analyzers`
- `PCL.Core` 通过以下方式引用：

```xml
<ItemGroup>
    <AdditionalFiles Include="App\IoC\LifecycleState.cs" />
    <ProjectReference Include="..\PCL.Core.SourceGenerators\PCL.Core.SourceGenerators.csproj"
                      OutputItemType="Analyzer"
                      ReferenceOutputAssembly="false" />
</ItemGroup>
```

`LifecycleState.cs` 作为 `AdditionalFiles` 传给生成器；`*.g.cs` 通过 `Compile Include="**\*.cs" Exclude="...;**\*.g.cs"` 排除手动编译（由生成器注入）。

## 2. 生成器一览

| 生成器 | 输入 | 输出 | 用途 |
|---|---|---|---|
| `ConfigGenerator` | `[ConfigItem]`、`[AnyConfigItem]`、`[ConfigGroup]`、`[RegisterConfigEvent]` | `ConfigService.g.cs` + 每个配置类的 `*.g.cs` | 生成配置属性访问器与初始化代码 |
| `LifecycleServiceTypesGenerator` | `[LifecycleService]` + `LifecycleState.cs` | `LifecycleServiceTypes.g.cs` | 生成按状态分组的服务类型表 |
| `LifecycleScopeGenerator` | `[LifecycleScope]` 类上的 `[LifecycleStart]`/`[LifecycleStop]`/`[LifecycleCommandHandler]`/`[LifecycleDependencyInjection]` | `<命名空间>.<类名>.g.cs` | 自动实现 `ILifecycleService` 与命令/DI 挂钩 |
| `DependencyCollectorGenerator` | `[DependencyCollector]`、`[DependencyInjectionPoint]` | `DependencyGroups.g.cs` + 每个注入点的 `*.g.cs` | 生成依赖收集与注入代码 |
| `EnvironmentInteropGenerator` | 编译时环境变量 `PCL_*`（需 `PCL_WRITE_SECRET=1`） | `EnvironmentInterop.g.cs` | 把环境变量写入 `SecretDictionary` |
| `LocalizedPropertyGenerator` | `[LocalizedProperty("Key")]` partial 属性 | `<类>.<属性>.Localized.g.cs` | 生成本地化 getter |

## 3. ConfigGenerator

### 3.1 输入

```csharp
public static partial class Config
{
    [ConfigGroup("Launch")]
    public static partial class LaunchConfigGroup
    {
        [ConfigItem<int>("LaunchRam", 2048)]
        public partial int Ram { get; set; }

        [AnyConfigItem<List<string>>("LaunchArgs")]
        public partial List<string> Args { get; set; }
    }

    [RegisterConfigEvent]
    public static ConfigEventRegistry Registry { get; } = ConfigEventRegistry.Create();
}
```

识别逻辑：

1. 语法层面筛选带特性的属性/类；
2. 语义层面确认特性类型为 `PCL.Core.App.Configuration.ConfigItemAttribute<T>` 或 `AnyConfigItemAttribute<T>`；
3. 解析 `ConfigSource`、默认值、组层级；
4. 收集 `[RegisterConfigEvent]` 的 `public static` 属性。

### 3.2 输出

- **每个配置类**：生成 partial 类的实例属性，getter/setter 委托给 `ConfigItem<T>`；嵌套组生成静态属性访问器。
- **`ConfigService.g.cs`**：生成 `ConfigService` 的初始化代码，把所有配置项、组、事件注册器登记进去，并按声明顺序建立键表。

### 3.3 约束

- 属性必须 `partial`，且实现 `get; set;`。
- 值类型默认值直接写在特性构造参数；复杂类型用 `[AnyConfigItem]`。
- 组必须 `partial class`，可嵌套。
- 配置类必须能被生成器识别（通常是 `Config` 及其嵌套类）。
- 生成失败时生成器会静默跳过（避免打断编译），但会导致配置属性缺失，需检查编译错误/生成文件。

## 4. LifecycleServiceTypesGenerator

### 4.1 输入

- `AdditionalFiles` 中的 `LifecycleState.cs`，用正则提取有效的枚举成员；
- 所有带 `[LifecycleService]` 的类，读取状态、优先级、是否异步。

### 4.2 输出

`LifecycleServiceTypes.g.cs`，典型结构：

```csharp
public static class LifecycleServiceTypes
{
    public static readonly Type[] BeforeLoading = [ typeof(...), ... ]; // 按 Priority 降序
    public static readonly Type[] Loading = [ ... ];
    // ...

    public static Type[] GetServiceTypes(LifecycleState state) => state switch
    {
        LifecycleState.BeforeLoading => BeforeLoading,
        LifecycleState.Loading => Loading,
        // ...
        _ => []
    };

    public static Dictionary<LifecycleState, Type[]> GetAllServiceTypes();
    public static (int StateCount, int TotalServices) GetStatistics();
}
```

生成时按 `Priority` 降序排序，因此同一状态内高优先级服务先启动。`AdditionalFiles` 中的 `LifecycleState.cs` 用正则提取枚举成员，新增状态无需改生成器。

### 4.3 注意

- 服务于 `LifecycleState` 枚举；新增状态时无需改生成器，只需改枚举。
- 服务类必须有无参构造。
- 同一 `Identifier` 只保留一个，重复会告警。

## 5. LifecycleScopeGenerator

### 5.1 输入

```csharp
[LifecycleService(LifecycleState.Loading, Priority = 100)]
[LifecycleScope("config", "配置")]
public sealed partial class ConfigService
{
    [LifecycleStart] private static void _Start(LifecycleContext ctx) { ... }
    [LifecycleStop]  private static Task _Stop(LifecycleContext ctx) => Task.CompletedTask;
    [LifecycleCommandHandler("config-get")]
    private static void _Cmd(CommandLine cmd) { ... }
    [LifecycleDependencyInjection("mods")]
    private static void _Inject(object target) { ... }
}
```

### 5.2 输出

为类生成 `partial` 实现：

- `Identifier`、`Name`、`SupportAsync`；
- `StartAsync`：按顺序调用 `[LifecycleStart]` 方法（同步/异步分别处理，支持参数注入 `LifecycleContext`）；
- `StopAsync`：调用 `[LifecycleStop]` 方法；
- 命令处理方法：把 `[LifecycleCommandHandler]` 包装成命令注册；
- 依赖注入方法：把 `[LifecycleDependencyInjection]` 包装成注入回调。

### 5.3 方法参数约定

生成器会检查方法参数并自动传入：

- `LifecycleContext`；
- `CommandLine` / 命令模型；
- `bool isCallback`（如需）；
- 拆分参数（按默认值/类型生成）。

具体签名以生成结果为准；建议保持“简单参数 + 明确默认值”。

## 6. DependencyCollectorGenerator

### 6.1 概念

- `[DependencyCollector<T>(identifier, targets)]`：声明一个“依赖收集器”特性，用于标记可被收集的类/属性/方法。
- `[DependencyInjectionPoint(identifier)]`：标记注入点，生成器会把匹配的依赖注入进去。

### 6.2 输出

- `DependencyGroups.g.cs`：按 `identifier` 分组的依赖表。
- 每个注入点一个 `*.g.cs`：生成“收集 + 注入”的方法。

用于把“横切关注点”（如配置迁移、UI 注册、命令处理器）通过特性聚合，避免手写长列表。

## 7. EnvironmentInteropGenerator

### 7.1 行为

- 仅当编译环境变量 `PCL_WRITE_SECRET=1` 时，收集所有 `PCL_` 前缀（排除 `PCL_WRITE_SECRET`）的非空环境变量；
- 生成 `EnvironmentInterop.g.cs`，写入 `SecretDictionary`；
- 为空时生成空字典。

### 7.2 安全注意

- 默认不写入任何密钥；CI 发布时才显式开启。
- 生成的源码会进入产物，**不要**在本地开发时随意开启，避免密钥泄漏。
- 运行时优先读取环境变量，其次读取生成的字典（见 `Secrets.cs`）。

## 8. LocalizedPropertyGenerator

### 8.1 输入

```csharp
public partial class LaunchPageViewModel
{
    [LocalizedProperty("Launch_Status_Ready")]
    public partial string StatusText { get; }
}
```

### 8.2 输出

```csharp
partial class LaunchPageViewModel
{
    public partial string StatusText => Lang.Text("Launch_Status_Ready");
}
```

特性：

- 只处理 `partial` 属性定义；
- 宿主类型必须是 `partial`；
- `Lang.Text` 在语言变化时不会自动通知，但 `LocalizedObservableObject` 会刷新所有本地化属性（见 `PCL.Core/ViewModel`）。

### 8.3 适用场景

只读的本地化文本属性（标题、标签、说明）。需要可变/可观察时，使用 `LocalizedObservableObject` + `OnPropertyChanged`。

## 9. 共享工具

`SharedConstants`：

- `AppNamespace = "PCL.Core.App"`
- `IocNamespace = "PCL.Core.App.IoC"`
- 各特性全名常量

`SharedExtensions`：

- 符号扩展：`GetSimplifiedTypeName`、`IsAttribute`、`IsPartial`、`GenerateTypeHeader`、`GetQualifiedSymbolName`、`ToLiteral` 等。

这些工具避免各生成器重复实现语法/符号处理。

## 10. 调试与验证

1. **查看生成文件**：在 `PCL.Core.csproj` 中临时设置

   ```xml
   <EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>
   <CompilerGeneratedFilesOutputPath>obj\generated</CompilerGeneratedFilesOutputPath>
   ```

   然后检查 `obj/generated/PCL.Core.SourceGenerators/...`。

2. **生成器调试**：在生成器代码中 `Debugger.Launch()`（源码中已有注释示例，不要提交）。
3. **常见问题**：
   - 属性不是 `partial` → 不生成；
   - 类不是 `partial` → 不生成；
   - 特性名字/命名空间不匹配 → 不生成；
   - `LifecycleState.cs` 未加入 `AdditionalFiles` → 状态列表为空；
   - `PCL_WRITE_SECRET` 未设置 → 环境变量字典为空（预期行为）。

## 11. 新增生成器的步骤

1. 在 `PCL.Core.SourceGenerators` 新建 `sealed class XxxGenerator : IIncrementalGenerator`；
2. 使用 `ForAttributeWithMetadataName` 或 `CreateSyntaxProvider` 做增量筛选；
3. 只做纯函数式转换，避免在生成阶段做 IO；
4. 用 `RegisterSourceOutput` 输出，命名遵循 `*.g.cs`；
5. 在 `PCL.Core.csproj` 中确认 `Compile Exclude="**\*.g.cs"`；
6. 为生成器补充测试（可放在 `PCL.Core.Test/Architecture` 或独立生成器测试项目）；
7. 更新本文档。

## 12. 设计原则

- **增量优先**：使用 `IIncrementalGenerator`，避免全量扫描。
- **失败不打断**：生成异常时尽量跳过（`ConfigGenerator` 的做法），但必须有可诊断日志/输出。
- **不生成业务逻辑**：生成器只补样板，不隐藏复杂流程。
- **输入显式**：依赖 `AdditionalFiles`/特性，而不是隐式约定。
- **安全默认**：密钥相关生成默认关闭。
